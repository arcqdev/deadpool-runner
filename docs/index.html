Features

Everything you need to stop babysitting builds.

Run it, forget it, and let the AI handle the rest.

🔄

Automatic Retry Loop

When your command exits non-zero, Deadpool Runner captures the error, sends it to an AI fixer, applies the patch, and retries — up to your configured limit.

🤖

AI-Powered Fixes

Ships with a built-in Codex client that understands your failure context, reads the repo, and writes targeted fixes. Pluggable architecture lets you swap in other ACP clients.

📡

Transparent Passthrough

Stdout and stderr stream to your terminal in real time. You see exactly what your command outputs while Deadpool captures it for analysis behind the scenes.

⚙️

Flexible Configuration

Per-repo config files, user-level defaults at ~/.config/deadpool-runner/, and CLI overrides. TypeScript config files with full type safety.

🛡️

Sandboxed Execution

Three sandbox modes — read-only, workspace-write, and full-access — so you control exactly how much power the AI fixer gets over your repo.

📝

Debug Artifacts

Every fix attempt saves solution.md, error logs, and input context to ~/.deadpool-runner/runs/ so you can review what happened and why.

How It Works

Four steps to self-healing scripts.

No configuration wizardry. Point it at a command and let it do its thing.

Run your command

Deadpool Runner executes your script, streaming output to the terminal while capturing stdout and stderr for analysis.

Detect failure

When the command exits with a non-zero code, the runner packages the error output, attempt count, and repo context into a structured failure report.

AI fixes the code

The failure context is sent to an ACP client (Codex by default) which reads your repo, diagnoses the issue, and applies a fix directly to your source files.

Retry automatically

The fixed command runs again. This loop continues until the command succeeds or the retry limit is reached. All fix attempts are saved as debug artifacts.

Quick Start

Up and running in under a minute.

Install globally, then point it at any failing command.

Install

# Install globally
npm install -g @arcqdev/deadpool-runner

# Or run directly with npx
npx @arcqdev/deadpool-runner -- npm test

Basic Usage

# Run with default config (reads deadpool-runner.config.ts)
dpr

# Pass a command directly
dpr -- npm test

# Set retry count and add context
dpr --retries 3 --prompt "This is a React app with Jest tests" -- pnpm test

# Verbose output with custom sandbox
dpr -v --sandbox danger-full-access -- pnpm build

Use as a Library

import { createRunner, loadConfig } from "@arcqdev/deadpool-runner";

const config = await loadConfig(process.cwd());
const runner = createRunner();
const result = await runner.run(config);
Configuration

Configure once, forget forever.

TypeScript config files with full type safety, user-level defaults, and CLI overrides.

📄 Project Config

// deadpool-runner.config.ts
import { defineConfig } from "@arcqdev/deadpool-runner";

export default defineConfig({
  command: "pnpm test",
  retries: 5,
  initialPrompt: "React 19 app, Vitest tests",
  maxOutputChars: 12000,
  acpClient: {
    name: "codex",
    model: "gpt-5.4",
    fullAuto: true,
  },
});

🌐 User Defaults

// ~/.config/deadpool-runner/config.json
{
  "retries": 5,
  "maxOutputChars": 12000,
  "acpClient": {
    "name": "codex",
    "model": "gpt-5.4",
    "fullAuto": true,
    "color": "never"
  }
}
CLI Reference

Every flag at a glance.

All options can also be set via config files.

Flag Description Default
--config <path> Path to config file auto-detect
--cwd, --repo <path> Working directory / target repo cwd
--client <name> ACP client to use codex
--retries <n> Max retry attempts after failure 5
--max-output-chars <n> Truncate captured output 12000
--prompt <text> Seed prompt / context for the fixer —
--model <name> Override model used by ACP client gpt-5.4
--sandbox <mode> read-only | workspace-write | danger-full-access workspace-write
--color <mode> Color output mode auto
--verbose, -v Show detailed ACP client logs false
--help, -h Show help —
